# BTC 历史行情库

在交易台左侧打开「历史行情」，选择 BTC 现货或 BTC USDT 永续。
「全部历史总览」以周线展示整个本地范围；可切换分钟至月线、跳转 UTC 日期、查看最早行情，向左拖动继续分页。十字光标显示 OHLC 与 BTC 成交量。

## 数据范围与质量

- Binance BTCUSDT 现货，从 2017-08-17 04:00 UTC 开始。
- Binance USD-M BTCUSDT 永续，从 2019-09-08 17:57 UTC 开始。
- 数据来自正式市场公开行情，与交易账户选中的 demo / paper / live 环境独立。这里只下载公开行情，不发订单。
- 使用 data.binance.vision 的 1m 月归档并验证官方 SHA256，官方 REST 补齐归档前的历史、最近月份与内部缺口。支持中断后继续，已完成归档不重复导入。
- 自动同步每 15 分钟运行；页面也可手动同步。只导入已经结束的分钟。
- 这是对应交易对自上线起的可获取历史，不包含币安上线前其他交易所的 BTC 报价。
- 早期归档有不对齐分钟的异常时间戳；这些记录不挪动时间、不直接入库，保留经校验的原始归档，再用官方 REST 补齐。排除数量存于 `archive_audit`。
- 官方仍无数据的分钟保留为缺口。页面提供数量、时间和缺少分钟数；不会补造平价 K 线。同步完成不等于交易所每一分钟都有记录。
- 小时以上周期使用持久化小时聚合加速；与原始数据共享修订标记，导入新数据时失效，并重建受影响部分。非整点的历史截断请求使用分钟原始数据，防止读到截断之后的样本。
- 所有聚合以 UTC 对齐，周线从周一开始，月线为自然月，3d 以 Unix epoch 对齐。聚合 K 线 `closed=false` 表示周期尚未结束或分钟样本不足。

## 文件和接口

- 原始分钟与小时聚合：`desk/engine/data/market.db`，独立 SQLite 历史库。
- 原始归档缓存：`desk/engine/data/market-archives/`。首次导入期间较早完成的归档可能只有已验证的数据库记录与校验和；缓存用于复核，图表读取数据库。
- 交易配置、指令文件、代理状态继续存储于 `desk.db`。
- `GET /api/history`：两类数据集的实际覆盖、同步状态与前 500 处缺口。
- `GET /api/history/klines?market=spot&interval=1d&end=0&limit=1500`：只读本地行情，无网络回退。`market` 为 `spot` 或 `um`，目前仅 BTCUSDT；`end` 为严格早于的 Unix 秒或毫秒，0 表示本地最新。
- 使用返回的 `nextEnd` 原值继续传给 `end`，依据 `hasMore` 判断更早数据。每次 1–5000 根，按时间正序返回。缺口中或晚于最新数据的游标会查找最近可用记录。
- `POST /api/history/sync?market=spot`：启动后台下载或继续同步，不启动交易代理。
- AI 只读工具 `get_history` 使用相同数据库，返回覆盖状态和分页 K 线。历史价格不会更新可成交价格快照；无需交易所密钥，也可在面板里持续分析查询结果。

开发时可在 `desk/engine` 执行 `go run ./cmd/history-sync`；加 `-market spot` 或 `-market um` 可只同步其中一个市场。引擎已经同步时优先使用页面操作。

## 验证

单元测试覆盖秒/毫秒/微秒解析、早期异常行、校验和拒绝、导入原子性、断点继续、市场隔离、OHLCV 聚合、UTC 周/月边界、缺口和分页、小时缓存失效以及截断不读未来数据。
浏览器测试覆盖桌面和手机的市场/周期切换、日期跳转、最早行情、全历史总览、缺口显示及无交易写入。

2026-10-19 首次下载后数据库 quick_check 通过；抽查 2017 首根/异常归档补齐、2019 永续首根、2020-03-12、2025 微秒归档等 7 根行情，OHLCV 均与官方 REST 一致。界面显示当前实时入库范围与根数，不使用此文档中的固定数字推断完整性。
