# 策略优化模式

代理栏顶部的「策略优化模式」开关独立于币安的 demo / paper / live 账户环境。

- 首次开启会停止当前代理执行，进入新的优化对话；原交易对话保留。
- 关闭会回到交易对话，保持停止。恢复交易需要主动点「启动」。
- 再次开启恢复先前的优化对话。两边分别保存最近 500 条消息，刷新或重启引擎后恢复当前模式与对应记录。
- 切换会取消持续运行与正在生成的面板回复，等待旧任务完全退出后再切换持久化状态。旧请求携带的对话标识过期时拒绝执行。
- 后端广播、HTTP 历史、模型上下文都按对话区分。模式变化时远端模型重新创建会话，本地当前对话的记录用于恢复上下文。

## 优化范围

优化模式每次模型请求前自动加载虚拟工作区的 `优化/INVEST.MD`：角色、研究流程、启动规则、未调用工具规则、等待结束规则、面板规则与工具协议均在此编辑，保存后下一次模型请求生效，无需重启。研究基线使用当前策略 JSON。

交易模式继续使用根目录 `INVEST.MD` 及可编辑的角色、场景、Tools 设置。两种模式不互相注入指令。引擎只发送启动、等待结束等事实事件；优化行为指令不在 Go 代码中拼接或回退。初始 Markdown 模板位于 `engine/internal/prompts/defaults/optimization.md`，仅在升级初始化时写入工作区，后续重启不覆盖用户编辑。缺失、空白或读取失败时停止请求并报错，不采用隐藏默认值。

原先运行时隐式附加的本地历史工具说明已一次性保存到可编辑的 Tools 配置，后续不会自动补回用户删除的说明。远端代理配置不再以代码默认角色兜底。

程序只允许本地历史与文件工具，持续运行时也允许 wait。优化记录仅可写到虚拟文件工作区的 `优化/` 目录；不能修改交易模式使用的根 `INVEST.MD` 或其他运行文件，也不会自动应用候选策略。

账户、持仓、当前行情、成交收益、提交决定、保护单工具均被优化模式拦截。手动平仓和保护单 API 同样拒绝优化模式下的写操作。仅切换开关不会启动模型或订单执行。

当前还未提供可执行的回测工具。研究指令明确要求区分“历史分析”和“已执行回测”，不得编造收益、交易数、验证通过或完成自动迭代的结论。完整的“回测 → 复盘 → 修正 → 再回测”需要后续接入回测执行器。

## 接口

- `GET /api/trader` 返回 mode、conversationId、switching 和运行状态。
- `PUT /api/agent/mode`，JSON 为 `{ "mode": "optimization", "conversationId": "trading" }`；关闭时交换两个模式值。
- `GET /api/agent/log?conversationId=optimization` 仅读取当前选中对话。
- `POST /api/agent/ask` 和 `/api/trader/start` 可携带 conversationId，防止延迟请求误入另一对话。

旧消息迁移到 trading 对话，原 ID 和正文保留；模式选择及每个对话的消息存储在现有 `desk.db`，历史行情库不受影响。

## 无工具回复与格式兼容

持续运行的回复没有解析出工具时，仅记录事实事件“上一轮回复未解析到工具调用”，立即进入下一次请求，由最新的工作区指令决定后续行动。不会认定研究完成，也不会强制等待 15 分钟；等待仅由实际执行的 `wait` 调用安排。

除原有 tool/json 代码块协议外，兼容模型遗漏代码块时独占行的 JSON 工具对象（查询、文件及等待工具）。不从普通行文、其他语言代码块、嵌套对象、JSON 数组或残缺 JSON 内提取工具；无代码块的交易决定与保护单操作不因此获得执行权限。
