# 交易台引擎维护

## INVEST.MD 常驻工作指令

根目录 `INVEST.MD` 保存非角色工作规则、开始运行要求和未调用工具时的处理要求，持续运行与面板对话均自动注入，保存后下一次模型请求生效。角色定义仍在「模型」设置；INVEST.MD 可从「文件」或「模型」的同名编辑器修改。升级会备份旧配置并原样迁移现有内容，不开启交易代理。详见 [Markdown 工作区](docs/markdown-workspace.md)。下文原提示词集中管理说明为旧版本记录。

## 提示词与行情选择

“模型”页面的“系统提示词与代理指令”统一管理 10 类指令：云端 system、交易模板、自定义交易说明、工具说明、面板对话、开始运行、未调用工具提醒、等待结束、连续调用提醒和历史引导。原策略提示词自动迁移；切换模型不会覆盖；保存后下一轮模型请求使用新配置。默认文本按钮仅填入草稿，仍需点击保存。保存不会启动交易代理。

策略只限定允许下单的合约、杠杆、持仓数量、名义价值和保证金。单笔名义价值上限 = 账户净值 × 净值倍数，不是保证金金额。例如净值 1,000 USDT、倍数 1 时，单笔名义价值不超过 1,000 USDT；5 倍杠杆对应约 200 USDT 保证金，实际还受保证金上限和可用资金约束。

代理的 get_market 可自行指定 symbol、interval、limit、end，可以查看下单名单以外的合约。已移除策略中的固定周期和 20–99 根限制；周期支持由币安接口决定，单次分页最多 1,500 根，需要更多历史时用 nextEnd 连续读取。历史价格不会被当成最新下单参考价。看板也可以选择完整合约列表和更多周期；交易风控不随行情查看范围扩大。

提示词接口：GET /api/settings/prompts、PUT /api/settings/prompts。持久化使用 settings.model_prompts，旧策略字段仅保留用于数据库迁移。单元与接口测试验证迁移、重启保留、非法保存不部分覆盖、风控保留及行情分页；浏览器测试使用模拟交易接口。

前端开发服务使用 `127.0.0.1:3210`，引擎使用 `127.0.0.1:8787`。引擎必须从 `desk/engine` 工作目录启动，才能沿用该目录的 `.env` 和 `data/desk.db`。

## 更新引擎

### 工具并行与等待

代理在同一条回复中输出多个独立的 tool JSON 代码块时，账户、持仓和不同币种/周期的行情查询会并行执行；每批最多同时进行 8 项，其余自动排队，不限制总调用次数。依赖返回值的查询（例如使用 nextEnd 翻页）应等上一项结果后再发起。提交交易决定按顺序执行，前面的查询完成后才下单，后续查询等待下单处理结束。

已移除旧版连续 6 轮后的强制 30 秒暂停，未调用工具时也不再强制暂停 30 秒。正常等待由代理主动调用 wait 决定；网络错误仍保留重试处理。“旧版连续调用提醒”仅为保存旧配置而保留，不再送入模型。Tools 管理中的工具说明可以编辑并行调用指引。

### 维护步骤

1. 在交易台停止 AI 交易代理，等待当前任务完成；维护期间不要启动代理、发送交易指令或手动下单。
2. 在 `desk/engine` 中构建候选程序：`go build -o desk.next.exe ./cmd/desk`。
3. 在 `desk` 目录运行 `powershell -NoProfile -File .\Restart-Engine.ps1`。默认只检查，不修改文件、不启动或停止进程。
4. 通过正常授权的执行环境运行 `powershell -NoProfile -File .\Restart-Engine.ps1 -Apply`，执行更新。

脚本只操作本项目的 `engine/desk.exe`，核对进程路径、启动时间和端口归属后停止旧进程。它在 `engine/data/engine-backups/` 保存旧程序和停止后的数据库文件，将候选程序复制到固定的 `desk.exe`，然后在正确工作目录中隐藏启动。后续构建仍然输出 `desk.next.exe`，避免覆盖正在运行的文件。

启动成功必须同时满足健康接口正常、模拟盘接口存在、交易代理停止、交易模式不变、原有代理历史仍可读取。启动失败会尝试恢复旧程序；数据库备份保留供人工恢复，不自动覆盖数据库。启动和回滚日志保存在 `engine/data/`。脚本不会切换账户、保存密钥或调用开始交易接口。

脚本适用于当前 `DESK_LISTEN=127.0.0.1:8787`、`DESK_DATA=data/desk.db` 的安装；发现不同配置、活动交易任务或无法核实进程身份时会停止。它要求现有引擎健康运行，不负责首次安装或离线恢复。

## 启用币安模拟盘

新引擎生效后刷新页面，进入“交易模式 / 交易所”，在“币安模拟盘 · U 本位合约”中填写模拟盘专用 API Key 和 Secret，点击“保存并启用模拟盘”，再测试连接。保存连接不会启动 AI 交易代理。密钥请直接填入界面。

## 执行环境的审批错误

如果工具报告 `Automatic approval review failed`，并返回 `403 Forbidden` / `This model is not available on the account's Excel BPS endpoint`，说明审批服务的模型与账户或端点不匹配，相关命令没有执行。这是审批调用失败，并不是审批已判定重启引擎不安全。

本机只读排查确认：Codex 用户配置选择 `model_provider=custom`、主会话模型 `gpt-6-astra`，提供方地址是 `api.daizongxiezuo.com` 的 `/v1` 接口。运行日志包含上述审批 403。日志没有明确记录失败审批请求所用的模型，不能据此假定它与主会话模型相同。当前交易台工作区未找到该网关实现，修复点在网关的审批模型路由、账户模型授权或客户端兼容配置。

有两条保留审批的处理路径：

- 服务维护者修复该账户的审批模型访问与路由，随后重试原来的审批流程。
- 若客户端的管理策略允许，由用户或管理员将 `approvals_reviewer` 设为 `user`，改由人工确认待审批操作，保持原有沙箱及审批策略。应在客户端重新加载配置或新会话中验证生效；当前被托管为 `auto_review` 的会话不自行改写其权限设置。若管理策略只允许自动审批，则需要管理员处理。

官方配置说明明确区分 `user` 和 `auto_review`，切换审批接收方本身不改变沙箱。参考来源：`https://learn.chatgpt.com/docs/config-file/config-reference`。

维护脚本不关闭审批、不更改 PowerShell 执行策略，也不规避权限检查。该外部审批故障不能通过交易台代码修复。

如果 PowerShell 报告“在此系统上禁止运行脚本”，脚本及其测试均未执行。这是与审批服务 403 独立的配置问题。本机检查结果是全部作用域 `Undefined`、有效策略 `Restricted`，未发现 `MachinePolicy` 或 `UserPolicy` 强制设置。

PowerShell 执行策略不是不可修改的锁。恢复正常审批后，可以按用户或组织允许的方式配置 `RemoteSigned` 或采用签名脚本；不需要关闭 Codex 审批或沙箱。Microsoft 文档说明 `Restricted` 允许单条命令而不允许脚本，`RemoteSigned` 允许本地编写的脚本，对互联网来源脚本要求签名。参考来源：`https://learn.microsoft.com/powershell/module/microsoft.powershell.core/about/about_execution_policies`。本次仅诊断，未修改任何策略。
