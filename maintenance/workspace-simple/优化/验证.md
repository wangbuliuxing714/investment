# 怎样验证

[返回流程](开始.md)

**状态：未执行回测。先补信号定义和执行器，再运行以下方案。**

## 开跑条件

1. [策略](策略.md)中的每项判断都有确定算法；同一份数据和配置可重现同一批交易。
2. 回测执行器能输出逐笔交易、费用、资金曲线及失败原因；不能只让 AI 看 K 线后估算收益。
3. 核对历史库覆盖、缺口、合约规则和成本来源；保存数据截止时间、策略配置及执行器版本。

## 数据与成交

| 项目 | 规则 |
| --- | --- |
| 标的 | BTCUSDT 永续；现货只作单独对照，不混用价格 |
| 数据 | 本地分钟库，15m/1h 可聚合；准确覆盖与缺口查历史数据页 |
| 样本 | 原计划：2020–2023 开发，2024 起验证；这些区间已被人工看过，不能称完全未触碰的样本外数据 |
| 防过拟合 | 开跑前冻结规则；采用滚动验证，并保留未用于调参的新区间做最终检验 |
| 信号与成交 | 只用当时已收盘、完整的 K 线；最早下一根开盘成交；缺口不补造、不交易 |
| 成本假设 | 手续费每边 0.05%；滑点基准每边 0.02%、压力每边 0.05%；均为待核对假设 |
| 资金费与强平 | 使用历史资金费、标记价和真实保证金档位；缺失时明确报告限制，代理价格或固定费率只算敏感性分析 |
| 同根路径 | 用更细数据判断；仍无法确定止损/止盈先后时采用保守顺序并标注 |

原记录中的 `1/杠杆−0.4%` 只是简化算式，不能替代交易所强平模型，也不能证明 1 倍杠杆永不爆仓。

## 第一轮只比较两组

同一信号、同一数据与成本：当前交易风险配置 vs 当前风险草案。先验证实现和风险，再研究参数；原有 A–G 组合暂不展开。

## 必须交付什么

- 可复现的运行编号、配置、数据区间、成本和完整逐笔明细。
- 扣费净收益、最大回撤、交易数、爆仓次数、最大单笔损失、持仓最大不利变动、最长水下时长、手续费与资金费。
- 基准与压力成本下的对照；明确未执行、失败、数据不足与已验证结果。

## 草案通过门槛（沿用原计划，尚未验证）

验证区间：爆仓 0 次、最大回撤不超过 30%、压力滑点下净收益为正、交易至少 30 笔、总交易成本不超过扣成本前正收益的 50%。水下超过 28 个月须单独评估资金占用。

门槛仅是研究筛选条件，不代表未来收益保证。样本不足不能判通过；低风险但无正收益也不能判通过。失败就记录证据并修正规则，不为通过而降低门槛或反复使用验证集调参。通过后仍需管理员决定是否进入模拟盘验证。
